## #6：播放頭「看得到的拖不動、拖得動的看不見」

> **狀態：✅ 已完成（第二梯，2026-10-06）** —— 抓柄常駐可見，仍只在波形軌段可拖（不跨三軌）。

### 現況

- 可見的播放頭 `.vt-playhead`（`video-edit-prototype.html:268-278`）：跨三軌（`top:0; bottom:0`）、
  2px 橘線，但 `pointer-events:none`（`:276`）——純視覺，不吃點擊。
- 可拖的刮動把手 `.vt-playhead-grip`（`:285-302`）：13px 寬命中區、`background:transparent`（平時隱形，
  只有 `:hover`／`.is-scrubbing` 才染 `--accent-soft`），且是 `#vt-timeline`（波形軌）的子節點
  （markup `:1888-1896`），高度隨波形軌，不跨三軌。
- 波形軌高 64px、字幕軌 44px、標題卡軌 1 車道 44px（＋gutter），三軌合計約 160px 上下 →
  把手實際可命中高度只有波形軌那段，約 **39%**。

**這是刻意的設計取捨，已寫在 CSS 註解裡**（`:279-284`）：前科是「absolute 把手整片蓋住標題卡／字幕軌
會吃掉底下按鈕點擊」（2026-08-25 lessons-learned，窄卡上點 × 變成默默拖時間）。所以故意不做成跨三軌寬把手。

### 根因

把手不可見 + 只有 39% 高，是為了「不蓋住下兩軌的可點元素」而付出的代價。使用者的困惑來自
**可見線與可拖區在空間上不重合**：看到整條線以為整條可拖，實際只有波形軌那截抓得到，且沒有任何視覺提示。

### 改法（下一梯若做）

不要回頭做跨三軌寬把手（會重蹈 2026-08-25 覆轍）。兩個低風險方向擇一：

1. **把手常駐微可見**：給 `.vt-playhead-grip` 一個平時就淡淡可見的頂部抓柄（例如波形軌頂端一顆
   6×6 的 accent 小菱形／橫條），讓「這裡可以抓」有視覺線索，但命中區仍只在波形軌、不下探。
2. **可見線頂端加 grip 把手圖示**：在 `.vt-playhead` 頂端（波形軌內）疊一個小三角 handle，
   `pointer-events` 只開在這顆 handle 上，維持「不蓋下兩軌」的底線。

驗收要用 `document.elementFromPoint` 斷言：(a) 波形軌內把手中心點命中的是 grip；
(b) 字幕軌／標題卡軌上同一 x 的點，命中的仍是底下的卡／按鈕而非 grip（守住前科底線）。

## #9：多來源載入失敗訊息黏成一段、含術語、順序不定

> **狀態：✅ 已完成（第二梯，2026-10-06）** —— 單一來源表 `LOAD_SOURCES`，固定順序、一項一行、技術細節收進 `title`。

### 現況

```js
// video-edit-prototype.js:2608-2612
function showEmptyNote(msg) {
  const note = $("vt-empty-note");
  note.textContent = note.hidden ? msg : `${note.textContent} ${msg}`;
  note.hidden = false;
}
```

四個來源各自在失敗時呼叫它：影片 `error` 事件（`:2876`）、波形 `:2888`、對齊 `:2671`、字幕 `:2903`。
真模式沒開集時這幾個會接連失敗，於是被一個空白串成一長段，例如：

> 影片載入失敗：真模式需要 app server 已開啟一集且該集有主影片（/api/video 回 200）。 波形載入失敗：真模式需要 app server 已開啟一集（/api/waveform 回 200）。 對齊設定載入失敗：/api/episode HTTP 503 字幕載入失敗：…

三個問題：(1) 訊息黏成一段、無分行／項目符號；(2) 含 `/api/video`、`HTTP 503` 等**對使用者無意義的術語**；
(3) 觸發順序取決於哪個 async 先 reject（影片走 `error` 事件、其餘走 `await` 鏈），所以每次排列可能不同。

### 根因

`showEmptyNote` 被設計成「逐次追加」，但追加分隔只有一個空白；且各呼叫點的文案是寫給開發者看的
除錯字串（帶端點與狀態碼），不是寫給使用者看的。沒有一個「把本次所有失敗彙整成一則清單」的收束點。

### 改法（下一梯若做）

- 改成**收集後一次渲染**：各載入流程把失敗原因 push 進一個陣列，init 收尾時若非空，一次渲染成
  帶項目符號的清單（`<ul>` 或換行），順序固定（影片→波形→字幕→對齊）。
- 文案拆成「給使用者的一句話 + 可選的技術細節」：主文去掉 `/api/…` 與狀態碼，技術細節收到
  次要樣式（如 `.vt-empty-note` 內的小字或 `title`），需要時才看。
- 保留「失敗不靜默」原則（CLAUDE.md）：仍要顯示錯誤，只是改成可讀的彙整，不是消音。

驗收：CDP 在真模式無集情境載入，斷言 `#vt-empty-note` 內是固定順序的清單、主文不含 `/api/` 與 `HTTP`。

## #12：快捷鍵只藏在 ⓘ 的 tooltip，無常駐提示

> **狀態：✅ 已完成（第二梯，2026-10-06）** —— ⓘ 改成按鈕＋popover，與「對齊」共用 `bindPopover`。

### 現況

時間軸標頭只有一顆淡色 ⓘ（`video-edit-prototype.html:1862-1867`），所有操作與快捷鍵塞在它的
`title=` 原生 tooltip：

```
拖曳＝標記剪除；點剪除段＝取消；⌘Z 復原 / 點字幕塊＝跳到右欄那一句 /
鍵盤：← → 移動播放頭（⇧ 跨大步）、I 進點、O 出點、⌫ 剪除、Esc 取消
```

`.vt-tl-hint`（CSS `:169`）只是把 ⓘ 染淡。tooltip 要滑過才出現、手機／鍵盤使用者拿不到、且一次顯示一大段。

### 根因

這其實是一次**刻意的收納**（註解 `:1861`「長 hint 已收成淡色 ⓘ」），把原本佔版面的長提示收起來。
副作用是快捷鍵從此「看不見」——而看不見的功能等於不存在（2026-08-09 content-draft
invisible-features-dont-exist）。

### 改法（下一梯若做，低優先）

此為體驗打磨、非 bug。可選：

- 最小動作：ⓘ 改成**可點開的 popover**（可沿用本梯 B 項新寫的 `.vt-align-pop` 那套 mount+popover 模式），
  點一下常駐顯示、再點收起，取代純 hover tooltip；鍵盤可聚焦、可開。
- 或：時間軸下方留一條極淡的常駐快捷鍵列（只列最常用的 3-4 個：空白播放、I/O、⌫）。

不建議把整段長提示常駐攤開（版面成本高，正是當初收起來的原因）。

## #13：圖示未沿用主編輯器 data-icon，混用手繪 SVG ＋ Unicode

> **狀態：✅ 已完成（2026-10-06，第三梯）— 選「接主系統」**。
> 判斷依據：`podcast_toolkit/web/static/icons.js` 是獨立 IIFE，只匯出 `window.Icons = {get, inject}`（`:116`），
> 不依賴 `app.js`／`app.css`、也不會自動 inject，所以原型只要多一行 `<script src="icons.js">`
> 就能用同一份圖示定義，不必引入主編輯器整包資產、也不必複製定義成第二份。
> 原型端只自寫數行 `[data-icon]` 的版面 CSS（對齊與 `pointer-events:none`，不是圖示定義）。
> `TOOL_ICONS` 與功能性 Unicode 字符已全數移除；`icons.js` 載入失敗時按鈕改顯示文字並進失敗清單，不靜默。
> 下文「現況／根因／改法」為動工前的紀錄，行號已過時。

### 現況

- 逐句小工具（切／併／卡／刪）用原型自繪的一組 inline SVG：`TOOL_ICONS`（`video-edit-prototype.js:998-1010`），
  在 `:1417` 以 `b.innerHTML = TOOL_ICONS[act]` 塞進按鈕。
- 其餘圖示則是 Unicode 字符：ⓘ（html `:1866`）、縮放 `-`／`+`（`:1850`／`:1853`）、摺疊箭頭 `▾`（`:1586`）等。
- 主編輯器（`app.js` / 字幕編輯器）用的是 `data-icon` 屬性驅動的統一圖示系統——原型沒接上去。

### 根因

原型是獨立的丟棄式頁面，當初為求快自畫了一組 icon，沒複用主編輯器的 `data-icon`。結果同一工具箱裡
手繪 SVG 與 Unicode 字符風格並存，粗細／視覺重量不一致。

### 改法（下一梯若做，低優先／一致性）

- 若 `data-icon` 系統可在不依賴主編輯器 CSS/JS 的前提下搬進原型：把 `TOOL_ICONS` 四顆與零散 Unicode
  字符統一改用 `data-icon`。
- 若搬過來成本過高（會牽動非本原型的檔，違反兩檔界線）：退而求其次，把 Unicode 功能字符
  （`-`／`+`／`▾`／ⓘ）也改成與 `TOOL_ICONS` 同一套手繪 SVG 風格，至少讓原型內部一致。
- **注意界線**：`data-icon` 定義多半在主編輯器資產裡，照抄進原型要小心別變成「動到第三個檔」。
  這條的 trade-off 要在動工前確認：是接主系統、還是原型內自洽。

## #14：標題卡面板兩句提示語意重疊

> **狀態：✅ 已完成（第二梯，2026-10-06）** —— 標頭註記改講另一條路（字幕列的「卡」鈕），「拖到藍軌」只留版型格下方一處。

### 現況

標題卡區裡兩句提示講同一件事：

- 區標頭 `.vt-side-note`（`video-edit-prototype.html:1588`）：「拖到藍軌，或在字幕列點『卡』」
- 版型格下方 `.vt-tpl-hint`（`:1660`）：「拖版型到藍軌新增一張卡」

兩句都在講「把版型拖到藍軌（標題卡軌）就會新增一張卡」。

### 根因

標頭的 note 與格子下方的 hint 是在不同時間各自加的，沒人回頭看另一句已經講過，於是重複。

### 改法（下一梯若做，低優先／文案）

兩句擇一、或拆分資訊不重疊：

- 建議：標頭 `.vt-side-note` 保留**替代入口**那半句（「在字幕列點『卡』也可新增」），
  把「拖到藍軌」這個主要手法留給版型格正下方的 `.vt-tpl-hint`（離實際拖曳源最近，提示該在那裡）。
- 或直接刪掉標頭那句，只留格下 hint。

純文案改動，驗收用目視即可（兩處不再出現同義的「拖到藍軌」）。
